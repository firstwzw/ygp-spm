# 待采列表性能优化技术方案

**日期**: 2026-09-15  
**问题单号**: SPM-9731  
**目标**: limit=300 时 P95 < 5000ms（当前 ~8704ms）

---

## 一、性能问题现状

### 1.1 压测数据

**环境**: DEV1  
**测试单号**: `GBT260915PERF1000ORD0001` (1000行待采，均为旧商品择商/SUPPLIER_SELECTION)  
**接口**: `POST /api/spm/admin/spmPendingPurchaseDetail/page`

| limit | 返回行数 | avg(ms) | p50(ms) | **p95(ms)** | 目标 | 达标 |
|------:|--------:|--------:|--------:|------------:|------|------|
| 100   | 100     | 3802    | 3842    | **4528**    | -    | -    |
| 300   | 300     | 8001    | 8037    | **8705**    | 5000 | ❌   |
| 1000  | 1000    | 14328   | 14052   | **15329**   | -    | -    |

**线性度**: ~8ms/row，说明主要耗时在 **per-row enrich**，而非 DB 分页本身。

## 二、根因分析

### 2.1 推测的调用链路

```
SpmPendingPurchaseDetailController.page()
 └─ SpmPendingPurchaseDetailService.spmPendingPurchaseDetailPage()
     ├─ [1] DB分页查询 (基础待采数据)
     ├─ [2] 并行enrich (N rows)
     │   ├─ fillRecommendSupplier() ← 推荐供应商
     │   ├─ fillPriceSourceOptions() ← 价源选项 (Quote/Selection lanes)
     │   ├─ fillNotes() ← 备注
     │   ├─ fillInventory() ← 库存
     │   └─ fillOmsInfo() ← OMS订单信息
     └─ [3] 构建分页结果
```

### 2.2 高概率N+1查询点

#### A. **推荐供应商获取** (`fillRecommendSupplier`)

**问题**:
```java
// 伪代码示例
for (PendingDetail detail : page.getRecords()) {
    // ❌ 单行调用
    List<Supplier> suppliers = supplierBindingService.getBindingSuppliers(
        detail.getSkuCode(), detail.getPurchaseQty()
    );
    // 内部可能再逐SKU调Feign: PMS获取binding、评级、leadtime
    detail.setRecommendSuppliers(suppliers);
}
```

**证据**:
- 择商逻辑需查询 `spm_supplier_goods_binding`（SKU+供应商绑定价）
- 需调 PMS Feign 获取供应商评级、leadtime
- 旧商品择商场景：1000行 × 2次查询 = 2000次I/O

#### B. **价源选项填充** (`fillPriceSourceOptions`)

**问题**:
```java
for (PendingDetail detail : page.getRecords()) {

            detail.getSkuCode(), detail.getSupplierCode()

        // ❌ 逐行查报价单

    }

```

**耗时**: 1000行 × 1-2次DB查询 = 1000-2000次

## 三、优化方案

### 3.1 核心原则

1. **批量查询**: 所有DB/Feign查询必须改为 `IN (id1, id2, ...)` 或批量接口
2. **并行执行**: 各enrich步骤之间无依赖，可用 `CompletableFuture` 并行
3. **缓存友好**: SKU基础信息、供应商评级等高频数据适合缓存

### 3.2 具体优化点

#### A. **推荐供应商批量化**

**Before**:
```java
for (PendingDetail detail : page.getRecords()) {
    List<Supplier> suppliers = getBindingSuppliersForSku(detail.getSkuCode());
    detail.setRecommendSuppliers(suppliers);
}
```

**After**:
```java
// 1. 批量查 binding
List<String> skuCodes = page.getRecords().stream()
    .map(PendingDetail::getSkuCode)
    .distinct()
    .collect(Collectors.toList());

Map<String, List<SupplierBinding>> bindingMap = 
    supplierBindingMapper.selectBatchBySkuCodes(skuCodes)
    .stream()
    .collect(Collectors.groupingBy(SupplierBinding::getSkuCode));

// 2. 批量调PMS Feign获取供应商信息
Set<String> supplierCodes = bindingMap.values().stream()
    .flatMap(List::stream)
    .map(SupplierBinding::getSupplierCode)
    .collect(Collectors.toSet());

Map<String, SupplierInfo> supplierInfoMap = 
    pmsFeignClient.batchGetSuppliers(new ArrayList<>(supplierCodes))
    .stream()
    .collect(Collectors.toMap(SupplierInfo::getCode, Function.identity()));

// 3. 组装
for (PendingDetail detail : page.getRecords()) {
    List<SupplierBinding> bindings = bindingMap.get(detail.getSkuCode());
    if (CollectionUtils.isNotEmpty(bindings)) {
        List<Supplier> enriched = bindings.stream()
            .map(b -> this.enrichSupplierInfo(b, supplierInfoMap))
            .sorted(this::compareByGrade) // 按评级排序
            .collect(Collectors.toList());
        detail.setRecommendSuppliers(enriched);
    }
}
```

**收益**: 1000次查询 → 1次DB + 1次Feign，减少 ~1998次I/O

#### B. **价源选项批量化**

**SUPPLIER_SELECTION场景**:
```java
// 收集所有 (sku, supplier) 对
List<SkuSupplierPair> pairs = page.getRecords().stream()
    .filter(d -> SUPPLIER_SELECTION.equals(d.getPriceSource()))
    .map(d -> new SkuSupplierPair(d.getSkuCode(), d.getSupplierCode()))
    .distinct()
    .collect(Collectors.toList());

// 批量查binding price
Map<SkuSupplierPair, BindingPrice> priceMap = 
    bindingMapper.selectBatchByPairs(pairs)
    .stream()
    .collect(Collectors.toMap(
        b -> new SkuSupplierPair(b.getSkuCode(), b.getSupplierCode()),
        Function.identity()
    ));

// 填充
page.getRecords().forEach(detail -> {
    if (SUPPLIER_SELECTION.equals(detail.getPriceSource())) {
        SkuSupplierPair key = new SkuSupplierPair(detail.getSkuCode(), detail.getSupplierCode());
        detail.setSelectable(priceMap.containsKey(key));
        detail.setBindingPrice(priceMap.get(key));
    }
});
```

**QUOTE_PRIORITY场景**:
```java
Set<String> quoteCodes = page.getRecords().stream()
    .filter(d -> QUOTE_PRIORITY.equals(d.getPriceSource()))
    .map(PendingDetail::getPurchasePriceCode)
    .filter(StringUtils::isNotBlank)
    .collect(Collectors.toSet());

Map<String, Quote> quoteMap = quoteMapper.selectBatchByCodes(quoteCodes)
    .stream()
    .collect(Collectors.toMap(Quote::getCode, Function.identity()));

        detail.setQuoteInfo(quoteMap.get(detail.getPurchasePriceCode()));

```

**收益**: 1000次 → 2次批量查询

### 3.3 并行执行优化

```java
public PageInfo<PendingDetailVO> spmPendingPurchaseDetailPage(QueryRequest req) {
    // 1. DB分页查询
    long t0 = System.currentTimeMillis();
    Page<PendingDetail> page = pendingDetailMapper.selectPage(req);
    long dbMs = System.currentTimeMillis() - t0;

    if (CollectionUtils.isEmpty(page.getRecords())) {
        return new PageInfo<>(Collections.emptyList(), page.getTotal());
    }

    // 2. 并行enrich
    long t1 = System.currentTimeMillis();
    CompletableFuture<Void> f1 = CompletableFuture.runAsync(
        () -> this.fillRecommendSupplierBatch(page.getRecords()), enrichExecutor
    );
    CompletableFuture<Void> f2 = CompletableFuture.runAsync(
        () -> this.fillPriceSourceOptionsBatch(page.getRecords()), enrichExecutor
    );
    CompletableFuture<Void> f3 = CompletableFuture.runAsync(
        () -> this.fillNotesBatch(page.getRecords()), enrichExecutor
    );
    CompletableFuture<Void> f4 = CompletableFuture.runAsync(
        () -> this.fillInventoryBatch(page.getRecords()), enrichExecutor
    );
    CompletableFuture<Void> f5 = CompletableFuture.runAsync(
        () -> this.fillOmsInfoBatch(page.getRecords()), enrichExecutor
    );

    CompletableFuture.allOf(f1, f2, f3, f4, f5).join();
    long enrichMs = System.currentTimeMillis() - t1;

    // 3. 转VO
    List<PendingDetailVO> vos = page.getRecords().stream()
        .map(this::toVO)
        .collect(Collectors.toList());

    long totalMs = System.currentTimeMillis() - t0;
    log.info("[SPM待采列表] dbMs={}, enrichMs={}, totalMs={}, limit={}", 
        dbMs, enrichMs, totalMs, req.getLimit());

    return new PageInfo<>(vos, page.getTotal());
}
```

**收益**:
- 原串行: 200ms(DB) + 5×1500ms(enrich) = 7700ms
- 现并行: 200ms(DB) + max(300ms/enrich) = 500ms

## 四、Mapper SQL优化

### 4.1 供应商绑定批量查询

```xml
<!-- SpmSupplierGoodsBindingMapper.xml -->
<select id="selectBatchBySkuCodes" resultType="com.ygp.spm.entity.SupplierGoodsBinding">
    SELECT 
        id, sku_code, supplier_code, purchase_price, lead_time,
        grade, active, creator, create_time
    FROM spm_supplier_goods_binding
    WHERE active = 1
      AND sku_code IN
      <foreach collection="skuCodes" item="sku" open="(" separator="," close=")">
          #{sku}
      </foreach>
    ORDER BY sku_code, grade DESC, purchase_price ASC
</select>

<!-- 需要索引 -->
-- CREATE INDEX idx_sku_active ON spm_supplier_goods_binding(sku_code, active);
```

### 4.2 绑定价批量查询（SUPPLIER_SELECTION场景）

```xml
<select id="selectBatchByPairs" resultType="com.ygp.spm.entity.SupplierGoodsBinding">
    SELECT 
        sku_code, supplier_code, purchase_price, lead_time
    FROM spm_supplier_goods_binding
    WHERE active = 1
      AND (sku_code, supplier_code) IN
      <foreach collection="pairs" item="pair" open="(" separator="," close=")">
          (#{pair.skuCode}, #{pair.supplierCode})
      </foreach>
</select>
```

**注意**: MySQL 8.0支持 `(col1, col2) IN ((v1, v2), ...)` 语法

### 4.3 报价单批量查询

```xml
<select id="selectBatchByCodes" resultType="com.ygp.spm.entity.Quote">
    SELECT 
        id, code, supplier_code, sku_code, quote_price, valid_start, valid_end
    FROM spm_quote
    WHERE active = 1
      AND code IN
      <foreach collection="codes" item="code" open="(" separator="," close=")">
          #{code}
      </foreach>
</select>
```

### 4.4 备注批量查询

```xml
<select id="selectBatchByBizIds" resultType="com.ygp.spm.entity.Note">
    SELECT 
        id, biz_id, biz_type, note_content, creator, create_time
    FROM spm_note
    WHERE active = 1
      AND biz_type = 'PENDING_DETAIL'
      AND biz_id IN
      <foreach collection="bizIds" item="id" open="(" separator="," close=")">
          #{id}
      </foreach>
    ORDER BY biz_id, create_time DESC
</select>
```

## 七、预期优化效果

### 7.1 I/O次数对比

| 操作 | 优化前 | 优化后 | 减少 |
|------|--------|--------|------|
| 推荐供应商 | 1000次DB + 1000次Feign | 1次DB + 1次Feign | -1998 |
| 价源选项 | 1000次DB | 2次DB（批量） | -998 |
| 备注 | 1000次DB | 1次DB | -999 |
| 库存 | 1000次Feign | 1次Feign（批量） | -999 |
| OMS信息 | 1000次Feign | 1次Feign（批量） | -999 |
| **合计** | **~5000次I/O** | **~10次I/O** | **-4990 (-99.8%)** |

### 7.2 延迟预估

**假设**:
- DB单次查询: 5ms
- Feign单次调用: 50ms
- 批量接口overhead: ×1.5

**优化前** (limit=300):
- DB分页: 50ms
- 推荐供应商: 300×5ms + 300×50ms = 16.5s
- 价源选项: 300×5ms = 1.5s
- 备注: 300×5ms = 1.5s
- 库存: 300×50ms = 15s
- OMS: 300×50ms = 15s
- **总计: ~50s** (实测8.7s说明有部分并行)

**优化后** (limit=300):
- DB分页: 50ms
- 并行enrich (max):
  - 推荐供应商: 1×5ms + 1×50ms×1.5 = 80ms
  - 价源选项: 2×5ms×1.5 = 15ms
  - 备注: 1×5ms×1.5 = 8ms
  - 库存: 1×50ms×1.5 = 75ms
  - OMS: 1×50ms×1.5 = 75ms
- **并行max**: 80ms
- **总计: 50 + 80 = 130ms**

**最终预估**: P95 < 500ms (含网络波动buffer)

✅ **远超目标 5000ms**
